# 2-Opt Local Search Algorithm for TSP

### 1. Introduction
The **2-Opt** (two-optimal) algorithm is a widely used local search heuristic designed for the Traveling Salesperson Problem (TSP). It starts with a complete tour and iteratively improves it by removing two non-adjacent edges, reconnecting the resulting paths to untangle crossings, and reversing the intermediate sub-tour segment if the operation reduces the overall tour length. The algorithm repeats until no further 2-edge exchange can reduce the tour cost (reaching a 2-optimal local minimum).

Use 2-Opt when:
- You need fast, high-quality approximate solutions for symmetric TSP without exponential exact solver costs.
- You want a post-processing heuristic to refine tours generated by nearest-neighbor, Christofides, or genetic algorithms.
- You require a clean, deterministic algorithm for routing and path-planning applications.

### 2. Usage

```csharp
using System;
using System.Collections.Generic;
using TspOptimization;

public class Example
{
    public static void Run()
    {
        // Define a set of 2D coordinates
        var points = new List<Point2D>
        {
            new Point2D(0, 0),
            new Point2D(1, 5),
            new Point2D(5, 5),
            new Point2D(5, 0),
            new Point2D(2, 2)
        };

        // Configure solver options
        var options = new TwoOptOptions
        {
            Strategy = TwoOptStrategy.BestImprovement,
            MaxIterations = 1000,
            UsePrecomputedDistanceMatrix = true,
            Tolerance = 1e-9
        };

        var solver = new TwoOptTspSolver(options);
        TspResult result = solver.Solve(points);

        // Output tour metrics
        // result.TourIndices contains the ordered node sequence
        // result.TotalDistance contains the total closed tour length
        // result.HasConverged indicates whether a 2-optimal state was achieved
    }
}
```

### 3. Detailed Explanation

1. **Delta Calculation ($O(1)$)**:
   Instead of recomputing the full tour distance after every potential edge swap, the delta $\Delta$ is computed in constant time:
   $$\Delta = (d(u_i, u_k) + d(u_{i+1}, u_{k+1})) - (d(u_i, u_{i+1}) + d(u_k, u_{k+1}))$$
   If $\Delta < 0$, the swap strictly decreases the tour length.

2. **Segment Inversion**:
   When an improving move is accepted, the subarray between index `i + 1` and `k` is reversed in-place via two-pointer swapping. This reconnects the tour correctly and maintains orientation.

3. **Search Strategies**:
   - **First Improvement**: Applies the first valid swap encountered with $\Delta < -\text{tolerance}$. This often converges faster in practice.
   - **Best Improvement**: Scans all $\approx N^2 / 2$ pairs in the current iteration, finds the move with the largest negative $\Delta$, and executes it.

4. **Edge Case Safety & Precomputation**:
   - Trivial inputs ($N \le 3$) are handled directly since every Hamiltonian cycle on $\le 3$ nodes has identical edge configurations.
   - Optional $O(N^2)$ precomputed distance matrix avoids repeated expensive `Math.Sqrt` calls.

---

### 4. Complexity Analysis

- **Time Complexity**:
  - **Distance Matrix Precomputation**: $O(N^2)$ where $N$ is the number of points.
  - **Single Iteration**: $O(N^2)$ pair evaluations with $O(1)$ delta checks and $O(N)$ segment reversal.
  - **Total Solver Time**: $O(k \cdot N^2)$, where $k$ is the number of improvement steps until convergence (typically $O(N)$ in practical Euclidean TSP scenarios, bounded by `MaxIterations`).

- **Space Complexity**:
  - With precomputed distance matrix: $O(N^2)$.
  - Without precomputed distance matrix (on-the-fly calculations): $O(N)$ for internal tour buffers.
